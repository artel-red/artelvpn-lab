# Что именно делает эвристика v0

Это описание реализованного алгоритма, а не доказательство его оптимальности.

На устройстве есть конечный список проверенных вариантов: вход, инфраструктурная группа, семейство транспорта и предварительная оценка длительности. Статистика хранится отдельно для локального сетевого контекста, ограниченно по памяти.

Для маршрута хранятся взвешенные успешные и неуспешные окончательные исходы `g`, `b`. Перед оценкой они затухают как `0.985 ** age` по условным раундам симуляции. Оценка полезного результата:

`q = (1 + g) / (2 + g + b)`.

Итоговый рейтинг состоит из этой оценки, ограниченной добавки за неопределённость, слабой подсказки других маршрутов той же инфраструктуры/семейства, небольшой предпочтительности последнего рабочего пути, штрафа за ожидаемое время и штрафа за сходство с уже неудачными/параллельными попытками.

Добавка неопределённости: `min(0.13, 0.08 * sqrt(log(1 + visits) / (1 + g + b)))`.

Подсказка похожих маршрутов исключает собственные наблюдения кандидата и имеет очень небольшой максимальный вклад. Непроверенным маршрутам не присваиваются ложные результаты. Причина отказа по этому признаку не устанавливается.

Штраф за сходство в текущем сеансе — `0.24` для той же инфраструктурной группы и `0.13` для того же транспортного семейства. Это фиксированные исследовательские параметры, не выведенные из российских измерений. Их оптимальность не проверена.

При отказе путь временно откладывается. Если доступны только пути с cooldown, алгоритм всё равно может проверить их: отсрочка не становится постоянным запретом. Последний рабочий вариант и временные отсрочки учитывают свежесть происхождения результата.

Уведомления о транспорте, аутентификации и полезных байтах не дают положительной терминальной метки сами по себе. Для обновления нужен итоговый `usable` или `unusable`. `unknown` удаляет ожидаемое наблюдение без обучения на выдуманной метке. Окончательный исход применяется только один раз, к правильному поколению контекста, с уменьшением веса при запоздании.

Защита бюджета и отмена параллельных попыток в v0 находятся в симуляторе исполнения. Голый класс контроллера нельзя считать готовым безопасным runtime для пользовательского приложения.

Эта эвристика не гарантирует постоянного исследования новых возможностей и может проигрывать простому резервному порядку или параллельному подбору. Следующий алгоритм следует проектировать на основании таких отрицательных результатов, сохраняя отдельную контрольную выборку.
