# Модель угроз

Проверяемые механизмы: недоступный адрес, имя, транспорт, исчерпание допустимой передачи, потери, задержки, отказ API и длительной передачи.
Нельзя приписывать любой timeout ТСПУ: это также может быть поломка маршрута, узла или конечного сервиса.

Противник может читать этот код, создавать аккаунты, получать публичные конфигурации, анализировать несколько потоков и менять правила.
Публикация алгоритма не должна требовать публикации действующих ключей и топологии.

При отсутствии достижимого пути выбор маршрута не создаёт новый канал. Белые списки проверяются отдельно от обычного мобильного интернета.
Промежуточное реле знает IP участника; сговор реле и выхода и корреляция времени остаются в модели угроз.
Рабочий туннель не устраняет cookies, вредоносное ПО и идентификацию аккаунтом.

Для исследований используем контролируемые конечные точки и синтетический трафик, с границами полномочий и лимитами нагрузки.
